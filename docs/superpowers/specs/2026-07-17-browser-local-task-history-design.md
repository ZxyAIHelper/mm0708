# 浏览器本地任务历史设计

## 目标

`product-swap` 的任务历史只保存在当前浏览器，不向 D1、R2、KV 或其他服务端存储写入任务、输入图或输出图。清除站点数据后历史消失；不提供跨设备同步。

## 存储

- localStorage 保存一个随机浏览器用户 ID，仅用于本地记录归属和未来数据迁移。
- IndexedDB 保存通用任务记录，主键为任务 ID，并为 `taskType`、`createdAt` 建索引。
- 输入图片以 Blob 保存到独立资源表，避免 Data URL 的 Base64 体积膨胀。
- 火山输出只保存 URL 字符串，不下载图片二进制。
- 图片资源默认保留 30 天；清理时删除 Blob，但保留任务的文本、状态、时间和资源占位信息。

## 通用任务模型

任务包含 `id`、`userId`、`taskType`、`status`、`title`、`input`、`result`、错误信息与创建/完成时间。当前类型为 `product_swap`，未来的“一键复制产品”等功能复用同一仓库和任务中心。

资源包含 `id`、`taskId`、`role`、`blob`、`sourceUrl`、MIME、大小、创建与过期时间。输入角色为 `target`、`product`、`scene`、`previous`；输出角色为 `output`。输出 URL 加载失败时显示“图片已过期”。

## 数据流

1. 页面加载时初始化 IndexedDB，并运行一次按时间清理。
2. 用户提交生成前创建 `processing` 任务并保存输入 Blob。
3. 火山接口成功后，将输出 URL、对话信息和完成状态写回本地任务。
4. 接口失败时保留失败任务及错误文本。
5. 任务中心从 IndexedDB 分页读取，使用 Blob URL 展示输入图，直接使用火山 URL 展示输出；图片加载失败转为过期占位。

## 服务端收缩

- 产品生成 API 恢复为无任务归档的纯生成接口。
- Worker 不挂载 `/api/tasks`，不运行图片清理定时任务，也不声明 R2 绑定。
- 已经执行的 D1 表保留为空表，不做破坏性回滚；线上功能不再读写这些表。

## 验证

- 单元测试覆盖 IndexedDB 仓库契约、任务状态变化、Blob/Data URL 转换和时间清理。
- 构建测试确认本地历史脚本进入发布产物。
- 浏览器冒烟覆盖生成、修正、历史列表、任务详情、输入/输出展示和过期占位。
- Worker 测试确认生成接口不依赖 D1/R2，打包结果不包含任务历史路由。
