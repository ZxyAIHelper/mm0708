# 微信聊天模板通用任务记录设计

## 目标

让“微信聊天截图”模板与其他生成模板使用相同的本地任务生命周期。用户每次点击“生成”或“重新生成整段对话”时创建一条任务记录；生成成功、失败均可在“作品”页查看，下载截图不重复创建任务。

同时把特殊模板与任务存储之间的边界抽象为通用生命周期接口，后续特殊模板不应再直接绕过任务记录。

## 当前问题

普通生成模板由 `script.js` 统一调用 `LocalTaskHistory.startTask`、`completeTask` 和 `failTask`。微信聊天模板挂载独立编辑器后提前结束通用启动流程，编辑器只负责请求对话、渲染截图和下载，没有任务生命周期依赖，因此生成不会落入 IndexedDB。

现有微信浏览器冒烟测试只验证生成、编辑、渲染和下载，没有断言任务被创建及完成，所以该缺口没有被测试捕获。

## 方案

采用依赖注入的通用 `taskLifecycle`：

- `script.js` 负责根据活动模板构造生命周期适配器。
- `WechatChatEditor.mountWechatChatEditor` 只调用注入的 `start`、`complete` 和 `fail`，不直接依赖 `LocalTaskHistory`。
- 未来的独立编辑器可以复用同一接口。
- 生命周期适配器不可用时，生成仍可继续，但界面必须提示任务记录未保存。

不在 API 客户端层自动记录。API 客户端不知道活动模板、最终渲染输出和用户可见的任务语义，不适合作为任务生命周期所有者。

## 数据流

每次点击生成按钮：

1. 编辑器校验聊天素材。
2. 调用 `taskLifecycle.start` 创建 `processing` 任务。
3. 请求 AI 对话草稿。
4. 使用草稿和聊天素材渲染全部截图页面。
5. 调用 `taskLifecycle.complete`，将任务变为 `completed`。
6. 若 AI 请求或截图渲染失败，调用 `taskLifecycle.fail`，将任务变为 `failed`。

重新生成执行同一流程并创建新任务。加载示例、编辑消息、切换头像、刷新预览和下载截图均不创建任务。

## 任务数据

任务使用微信模板清单中的：

- `taskType: wechat_chat_screenshot`
- 模板名称作为标题
- `templateId: wechat-chat-screenshot`

输入元数据只保存安全、可恢复的摘要：

- 店铺名称
- 补充要求
- 地点名称与地址
- 是否包含图片、地点及对应数量

用户上传图片继续作为任务输入资产保存，不把 Data URL 写进任务元数据。

成功结果保存所有渲染页：

- 第一张截图作为任务列表预览
- 每一张截图作为按顺序排列的 `output` 资产
- 结果元数据记录页数
- 本地 Blob 不重复编码进 `result.imageUrl`，避免第一张大图在 IndexedDB 中保存两份

普通单图模板继续兼容现有 `imageUrl` 输入。任务仓库扩展为可接受多输出，但不改变现有调用方行为。

## 错误处理

- AI 或渲染失败：任务标记为 `failed`，保留安全错误码与错误文案。
- 任务创建失败：不请求 `complete` 或 `fail`，AI 生成可以继续；编辑器显示“生成可继续，但本次任务记录无法保存”。
- 成功结果落库失败：生成结果仍显示；编辑器显示“生成成功，但任务记录保存失败”。
- 不自动重试外部接口或任务写入。

## 测试

所有测试使用本地固定响应、fake IndexedDB 边界或请求拦截，不调用真实 AI、腾讯地图或计费接口。

测试覆盖：

- 微信编辑器每次生成依次调用 `start` 和 `complete`。
- AI 或渲染失败时调用 `fail`。
- 任务创建失败不阻断生成，并显示记录失败提示。
- 下载、编辑和刷新预览不创建任务。
- 多页完成结果保存全部输出，首张作为预览。
- 普通单图模板的任务完成行为保持兼容。
- 微信浏览器冒烟测试断言 IndexedDB 中存在一条 `completed` 的 `wechat_chat_screenshot` 任务，并能从“作品”页看到。

## 成功标准

- 微信聊天模板每次 AI 生成或重新生成都会产生一条任务记录。
- 成功、失败状态与其他模板一致。
- 多页截图均可在任务详情中查看，首张用于列表预览。
- 下载操作不会产生重复记录。
- 特殊模板通过通用生命周期接口接入任务记录。
- 验证过程中的真实 AI、地图和计费接口调用次数均为零。
