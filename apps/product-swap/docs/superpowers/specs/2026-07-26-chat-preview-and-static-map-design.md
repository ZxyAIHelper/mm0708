# 聊天预览比例、备用地点标记与静态地图设计

## 目标

修复网页中的聊天截图预览被压缩为 `9/16` 的显示问题；明确标记后端提供的备用地点；在不暴露腾讯地图 Key 的前提下，让编辑页和导出 PNG 复用真实的腾讯静态地图。

## 范围

本次仅调整 `product-swap` 微信聊天截图模板的前端：

- 网页预览保持 canvas 自身的 `1179×2556` 比例。
- 备用地点在搜索结果和已选地点摘要中显示“备用位置”。
- 已选地点摘要显示腾讯静态地图预览。
- 导出 PNG 继续使用现有服务端 `/map-preview` 静态图代理。
- 同一坐标在一次页面会话中最多加载一次静态地图，失败后不自动重试。
- 静态地图失败时明确显示“地图暂不可用”，不再显示灰底绿色圆点。

不修改导出画布尺寸、聊天排版、地图搜索后端或腾讯地图 Key 的存储方式，也不接入浏览器 JavaScript SDK。

## 比例修复

导出 canvas 已正确设置为 `1179×2556`。网页预览变形的根因是 `.chat-preview-canvas` 额外设置了 `aspect-ratio: 9 / 16`。

修复后 CSS 使用 canvas 的固有宽高比：

```css
.chat-preview-canvas {
    display: block;
    width: 100%;
    height: auto;
    background: #ededed;
}
```

这只影响网页显示，不修改 canvas 属性或下载的 PNG。

## 备用地点数据流

后端兜底地点已经返回 `fallback: true`。前端按以下路径保留标记：

1. `tencent-map-picker.js` 的搜索结果规范化保留布尔值 `fallback`。
2. `chat-materials.js` 的地点规范化保留布尔值 `fallback`，供编辑器状态使用。
3. 搜索状态改为“地图暂不可用，已提供备用地点”。
4. 搜索结果和已选地点摘要显示“备用位置”徽标。
5. `chat-draft-client.js` 构造 AI 请求时，只序列化 `id`、`name`、`address`、`city`、`lat` 和 `lng`，不发送 `fallback`。

“备用位置”只用于编辑器提示，不画进最终聊天截图。

## 静态地图加载

继续使用现有服务端接口：

```text
/api/product-swap/map-preview?lat=<lat>&lng=<lng>&v=2
```

该接口由 Cloudflare Worker 请求腾讯 `staticmap/v2`，因此 Key 保持在服务端。

`tencent-map-picker.js` 增加会话级地图图片缓存：

- 以完整静态图 URL 为键。
- 第一次调用创建并缓存一个图片加载 Promise。
- 成功时，编辑器摘要和 canvas renderer 复用同一个已加载图片。
- 失败时缓存空结果，本次页面会话不再请求相同 URL。
- 页面刷新后缓存重置，Key 恢复时可重新请求。

地点搜索结果列表不批量加载地图，避免一次搜索产生最多 12 次静态图调用。只有用户选中的地点加载一次。

## 地图失败显示

编辑器中的已选地点摘要：

- 加载中显示“正在加载地图…”。
- 成功后显示真实静态地图。
- 失败后显示“地图暂不可用”，并保留名称、地址及清除按钮。

导出 canvas 中的地点卡片：

- 成功时绘制静态地图。
- 失败时绘制浅灰背景和“地图暂不可用”文字。
- 不再绘制绿色圆点，以免被误认为真实地图。

## 测试

所有测试使用本地数据或注入的图片 loader：

- CSS 契约测试断言预览不再包含 `aspect-ratio: 9 / 16`，且使用 `height: auto`。
- 地点规范化测试断言 `fallback: true` 被保留。
- AI 请求测试断言 `fallback` 不出现在请求 JSON 中。
- 编辑器契约测试断言备用徽标和地图状态文案存在。
- 地图缓存测试断言同一 URL 的 loader 只调用一次，失败后也不重试。
- renderer 测试断言无地图图片时绘制“地图暂不可用”，导出尺寸仍为 `1179×2556`。
- 浏览器冒烟测试继续拦截 API，不访问腾讯地图或豆包。

## 成功标准

- 网页预览与导出 PNG 使用相同宽高比。
- 用户能明确识别备用地点。
- 备用标记不会进入 AI 请求或最终截图。
- 选中地点成功加载时，编辑器和导出图显示真实腾讯静态地图。
- 同一坐标每次页面会话最多请求一次，失败不重试。
- 验证过程中真实腾讯地图和豆包调用次数均为零。
