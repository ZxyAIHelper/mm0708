# 微信聊天截图模板设计

## 目标

在现有模板系统中新增“微信聊天截图”模板。用户提供店铺名称、店铺图片或腾讯地图真实地点中的任意一种素材，AI 生成自然的双人单聊内容，浏览器再把结构化对话稳定渲染成可编辑、可导出的微信风格聊天截图。

首版优先保证真实地点、中文可读性和可控编辑，不让图像模型直接生成整张聊天图。后续若确定性模板的视觉表现不足，再以已渲染截图为底图增加可选的 AI 美化。

## 范围

- 新模板 ID：`wechat-chat-screenshot`
- 单聊模式，消息分为左侧“朋友”和右侧“我”
- 可输入：
  - 店铺名称，最多 60 字
  - 1～3 张 JPG、PNG 或 WebP 图片
  - 1 个通过腾讯地图选点组件确认的真实地点
  - 补充要求，最多 200 字
- 店铺名称、图片、地点三类素材至少填写一类
- AI 返回完整消息顺序、左右发送方和消息类型
- 消息类型只支持文本、图片引用和地点引用
- 生成后支持修改文本、切换左右、删除单条消息和整段重生成
- 固定导出 1080×1920 PNG；预览按容器等比缩放
- 首版不支持群聊、语音、红包、视频、表情包、转账和聊天记录拼接

## 方案选择

采用“结构化 AI 对话 + 本地确定性渲染”的混合方案。

不采用纯 AI 出图，因为图像模型无法稳定保证中文、真实地址和微信消息布局。也不采用纯固定文案，因为用户希望夸奖对话由 AI 完整生成。后端文本模型只决定对话内容和素材插入顺序；前端渲染器拥有最终视觉控制权。

AI 美化作为后续独立能力，不进入首版生成主路径。即使未来增加美化，也必须锁定文字和地址，不允许模型改写真实地点。

## 页面结构

该模板继续使用 `/create.html?template=wechat-chat-screenshot`，但创建页为它挂载独立的聊天编辑器控制器，避免把复杂状态继续堆入通用字段渲染逻辑。

页面分为三部分：

1. 素材区
   - 店铺名称输入框
   - 图片上传卡片，最多 3 张，可删除和排序
   - “选择店铺位置”按钮；选中后显示地点名称、地址和小地图预览
   - 补充要求输入框
2. 聊天预览区
   - 手机比例画布
   - 微信风格顶部栏、时间分隔、头像、左右气泡、图片消息和地点卡片
   - 消息列表编辑器
3. 操作区
   - 首次为“生成对话”
   - 已生成后提供“重新生成”“导出 PNG”
   - 单条文本可编辑；每条消息可切换左右或删除

点击生成时先校验三类素材至少存在一类。生成过程中保留所有输入，只禁用重复提交。AI 返回后先通过严格校验，再进入预览。

## 腾讯地图接入

使用腾讯位置服务官方地图选点组件，以 iframe 方式打开：

```text
https://apis.map.qq.com/tools/locpicker
  ?search=1
  &type=1
  &key=<public-key>
  &referer=<configured-referer>
```

父页面只接受来源为 `https://apis.map.qq.com` 且 `data.module === "locationPicker"` 的 `postMessage`。选点结果规范化为：

```js
{
  id: 'store-location',
  name: '颐和园',
  address: '北京市海淀区新建宫门路19号',
  city: '北京市',
  lat: 39.998766,
  lng: 116.273938
}
```

名称、地址和坐标必须来自选点组件，用户不能手工改写坐标。用户可以清除地点并重新选择。

聊天地点卡片使用腾讯静态图 API V2 生成真实坐标缩略图。为避免密钥散落、跨域图片污染 Canvas，浏览器通过后端受限代理获取预览：

```text
GET /api/product-swap/map-preview?lat=39.998766&lng=116.273938
```

代理固定图片尺寸、缩放级别、地图类型和标记样式，只接受合法中国境内经纬度，设置短期公共缓存，不允许调用方传入任意上游 URL。

前端通过：

```text
GET /api/product-swap/map-config
```

读取地图选点组件所需的公开 Key 和 referer。腾讯控制台必须为 Key 配置允许的站点域名，并按官方要求把地图组件域名加入白名单。若地图配置缺失，只禁用地点选择；名称和图片输入仍可使用。

## 输入数据

模板清单新增复合字段类型：

```js
{
  key: 'chatSource',
  type: 'chat-materials',
  label: '聊天素材',
  required: true,
  minSources: 1,
  maxImages: 3,
  accept: ['image/jpeg', 'image/png', 'image/webp']
}
```

前端提交给聊天生成接口的数据：

```js
{
  templateId: 'wechat-chat-screenshot',
  storeName: '三山山',
  images: [
    {
      id: 'image-1',
      dataUrl: 'data:image/webp;base64,...'
    }
  ],
  location: {
    id: 'store-location',
    name: '三山山',
    address: '浙江省台州市椒江区...',
    city: '台州市',
    lat: 28.0,
    lng: 121.0
  },
  requirements: '语气像朋友刚吃完后随手分享'
}
```

图片复用现有格式、体积、尺寸和解码校验。对象只接受声明字段，字符串统一去首尾空格，数组必须是普通稠密数组。至少满足 `storeName` 非空、`images` 非空或 `location` 存在之一。

## AI 对话接口

新增：

```text
POST /api/product-swap/chat-draft
```

后端复用已有豆包聊天模型配置，不调用图片生成端点。系统提示要求模型只输出 JSON，禁止 Markdown 代码围栏和解释性文字。

响应结构：

```json
{
  "success": true,
  "draft": {
    "version": 1,
    "contactName": "小林",
    "messages": [
      {
        "id": "message-1",
        "side": "right",
        "type": "location_ref",
        "refId": "store-location"
      },
      {
        "id": "message-2",
        "side": "left",
        "type": "text",
        "text": "这家我去过，环境和味道都挺舒服的。"
      }
    ]
  },
  "provider": "volcano",
  "requestId": "chat_..."
}
```

约束：

- `contactName` 为 1～12 个普通字符，不包含营销词或联系方式
- 生成 6～10 条消息，左右双方都至少出现一次
- 文本每条 1～80 字，总文本不超过 500 字
- 语气像真实朋友聊天，允许口语和短句，不写整齐划一的广告文案
- `image_ref` 和 `location_ref` 只能引用请求中存在的 ID
- 每个已提供的图片和地点必须且只能引用一次
- 店铺名称存在时至少在一条文本或地点卡片中出现
- 不编造价格、优惠、销量、详细菜名、联系方式或未提供的地址
- 不输出外链、HTML、Markdown、指令或新的素材

服务端解析时允许剥离一层意外代码围栏，但不容忍额外字段、未知类型、越界长度、重复 ID 或不存在的素材引用。第一次结构校验失败时，用错误摘要要求模型修复一次；再次失败则返回稳定错误 `INVALID_CHAT_DRAFT`。

## 可编辑回退

前端内置一套不冒充 AI 结果的“示例对话”。网络失败或 AI 结构连续无效时，页面提示“AI 对话暂时不可用”，并允许用户一键载入示例继续编辑。

示例对话不编造素材：

- 有地点时插入真实地点卡片
- 有图片时逐张插入图片消息
- 有店名时使用“这家店”“刚去的地方”等安全短句，并只在素材中已有名称时显示名称

回退不会自动导出，用户仍需确认预览。

## 聊天渲染器

新增独立的纯数据渲染器。输入为已验证的 draft 和素材表，输出为 Canvas。DOM 编辑器和 Canvas 导出共用同一份标准化消息数据，避免预览与成图不一致。

固定视觉规格：

- 画布 1080×1920
- 顶部状态栏和聊天标题栏使用中性微信风格，不复制微信 Logo
- 背景为浅灰，左右使用白色与绿色气泡
- 文本按中文字符、英文单词和标点安全换行
- 头像使用仓库内自带的两张中性插画头像
- 图片消息保持原图比例，在安全最大框内裁切
- 地点卡片包含真实静态地图、地点名和地址
- 根据消息高度自动计算纵向间距；消息超出可用区域时拒绝导出并提示删减，而不是缩小到不可读

导出前必须确认所有图片和地图缩略图已经解码。Canvas 只绘制同源 Data URL 或后端代理返回的数据，避免跨域污染。PNG 下载文件名使用：

```text
微信聊天截图-YYYYMMDD-HHmm.png
```

## 消息编辑

生成后的编辑仅修改本地 draft：

- 文本消息可直接编辑，继续应用 80 字上限
- 任意消息可切换左侧或右侧
- 任意消息可删除
- 图片和地点消息不能改成不存在的引用
- 至少保留 2 条消息，且左右双方各至少 1 条

“重新生成”会保留当前素材和补充要求，但用新的 AI draft 替换当前对话。替换前保留旧 draft；若请求失败则继续显示旧内容。

## 代码边界

前端：

- `template-packs/wechat-chat-screenshot/manifest.js`：模板元数据和复合字段声明
- `chat-materials.js`：输入规范化、校验和素材 ID 管理
- `tencent-map-picker.js`：配置读取、iframe 生命周期、可信消息接收和地图缩略图加载
- `chat-draft-client.js`：聊天接口调用与响应规范化
- `wechat-chat-renderer.js`：布局计算、Canvas 绘制和 PNG 导出
- `wechat-chat-editor.js`：页面状态与交互编排
- `script.js`：只负责识别复合字段并挂载编辑器

共享 API：

- `apps/my-cloud-hub/src/projects/product-swap/chat-draft.ts`：请求和 AI JSON 校验
- `apps/my-cloud-hub/src/projects/product-swap/chat-provider.ts`：豆包文本调用
- `apps/my-cloud-hub/src/projects/product-swap/router.ts`：聊天、地图配置和地图预览路由
- `apps/my-cloud-hub/src/projects/product-swap/provider.ts`：增加腾讯地图环境变量类型

静态站 Worker 不代理 AI 请求，继续使用 `api.mm0708.top`；创建页通过现有 `ProductSwapApi` 调用共享 API。

## 错误处理

- 三类素材均为空：`INVALID_INPUT`，提示“请至少填写店铺名称、上传图片或选择地点”
- 图片超限或无效：沿用现有图片错误
- 地图未配置：地点按钮禁用，其他素材可继续
- 选点 iframe 加载失败：保留当前输入，允许重试或关闭
- 非可信 `postMessage`：静默忽略
- 地图预览失败：地点仍保留，以灰色占位地图导出并显示非阻塞提示
- AI 超时或上游失败：保留当前 draft，提供重试和示例回退
- AI JSON 无效：服务端修复一次，仍无效则返回 `INVALID_CHAT_DRAFT`
- 消息超出画布：禁止导出，定位到过长消息并提示删减
- 导出失败：不清除 draft，允许重新加载素材后重试

## 安全与隐私

- 用户要求生成夸奖内容，但不得伪造消费事实、具体优惠、销量或无法验证的菜品信息
- 地点名称、地址和坐标只接受腾讯地图选点结果
- AI 输入中的名称、地址和补充要求均视为不可信文本，使用清晰分隔并禁止提升为系统指令
- 服务端限制请求体、图片数量、文本长度、响应体和上游超时
- 地图预览代理只构造固定腾讯 API URL，不接受任意远程地址，防止 SSRF
- 前端使用 `textContent` 和 Canvas API 显示 AI 文本，不注入 HTML
- 首版不把聊天 draft 写入服务端历史；本地刷新恢复沿用现有 IndexedDB 机制时只保存规范化数据和用户素材

## 测试

单元测试：

- 模板清单注册和 `chat-materials` 字段校验
- 三类素材“任选一个但至少一个”的所有组合
- 图片数量、大小、格式和重复 ID
- 腾讯选点消息来源、module、字段和坐标校验
- AI draft 的类型、长度、引用完整性和未知字段拒绝
- AI 无效 JSON 的单次修复及稳定失败
- 消息编辑后的最小数量和左右双方校验
- 中文换行、图片尺寸、地点卡片和画布溢出计算
- 地图预览代理参数、上游 URL 固定性、缓存和失败映射

浏览器测试：

- 只填店名可生成并导出
- 只上传图片可生成并导出
- 只选择真实地点可生成地图卡片并导出
- 三类素材同时存在时，每项在聊天中只出现一次
- 修改文字、切换左右、删除消息后预览与 PNG 一致
- AI 失败时可载入示例，旧 draft 不丢失
- 手机和桌面宽度下表单、预览、地图弹层均可操作

视觉检查：

- 中文、地址和店名清晰可读
- 左右气泡、头像、图片和地点卡片没有重叠
- 1080×1920 导出无裁切、无跨域空白、无第三方水印
- 与微信单聊有明确相似感，但不展示微信 Logo 或伪造系统身份

## 验收标准

- 新模板出现在模板目录并可进入创建页
- 名称、图片、地点至少输入一项即可提交，全部为空时不可提交
- 地点由腾讯地图真实搜索选择并在最终截图中显示真实名称、地址和坐标对应地图
- AI 返回完整的 6～10 条单聊结构，所有素材引用合法且完整
- 用户可以修改文本、切换左右、删除消息和重新生成
- 预览可稳定导出 1080×1920 PNG，中文和地点信息清晰
- AI 或地图服务失败时不丢失用户输入，并有可继续完成任务的回退路径
