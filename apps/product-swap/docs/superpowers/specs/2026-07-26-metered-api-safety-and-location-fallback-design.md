# 额度接口安全与地点搜索兜底设计

## 目标

避免自动化测试、冒烟测试和调试过程消耗腾讯地图、豆包 AI 等真实接口的额度；当腾讯地图不可用时，地点选择仍可继续完成，并稳定返回“深圳湖贝里”作为兜底地点。

## 范围

本次包含两项改动：

1. 在仓库根目录新增 `AGENTS.md`，约束所有需要 Key、存在额度或可能计费的外部调用。
2. 修改 `my-cloud-hub` 的地点搜索代理：外部服务失败时不重试，改为返回固定地点。

不修改聊天生成逻辑、截图样式、地图展示样式，也不新增第三方服务。

## 外部接口调用约束

根目录 `AGENTS.md` 将明确要求：

- 自动化测试、冒烟测试、CI 和重复调试默认禁止调用真实的额度或计费接口。
- 测试必须注入 mock、fake 或本地固定响应；不得通过设置 live-test 环境变量绕过限制。
- 只有用户明确要求真实验收时，才允许进行一次真实调用；调用前必须说明将使用哪个接口。
- 真实调用禁止自动重试、批量请求和轮询；首次失败后立即停止。
- API Key 只能保存在服务端 Secret 中，不得写入前端、日志、测试快照、响应或截图。
- 验证外部失败场景时必须使用 mock，不能为了制造失败而请求真实服务。
- 发起任何可能消耗额度的请求前，应确认请求次数有明确上限。

这些规则适用于腾讯地图、豆包 AI，以及今后接入的同类服务。

## 地点搜索行为

现有 `/location-search` 接口继续校验 `region` 和 `keyword`：

- 参数缺失、为空或超过长度限制时，返回 HTTP 400；输入错误不使用兜底地点。
- 腾讯地图正常返回时，沿用当前结果结构，最多返回 12 个真实地点。
- 腾讯地图 Key 缺失、网络异常、超时、非 2xx、响应过大、JSON 无效、上游业务状态非成功或额度耗尽时，不重试上游请求，直接返回固定地点。
- 腾讯地图正常响应但搜索结果为空时，返回空数组。这属于有效搜索结果，不视为外部故障。

固定地点为：

```json
{
  "id": "fallback-shenzhen-hubeili",
  "name": "深圳湖贝里",
  "address": "深圳市罗湖区湖贝路1068号",
  "city": "深圳市",
  "lat": 22.546394,
  "lng": 114.128133,
  "fallback": true
}
```

## 响应契约

发生外部故障时，接口返回 HTTP 200：

```json
{
  "success": true,
  "locations": [
    {
      "id": "fallback-shenzhen-hubeili",
      "name": "深圳湖贝里",
      "address": "深圳市罗湖区湖贝路1068号",
      "city": "深圳市",
      "lat": 22.546394,
      "lng": 114.128133,
      "fallback": true
    }
  ],
  "fallback": true,
  "fallbackReason": "quota_exhausted"
}
```

`fallbackReason` 只使用有限枚举值：

- `not_configured`
- `upstream_unavailable`
- `quota_exhausted`

它不包含 Key、上游原始响应或其他敏感信息。兜底响应设置 `Cache-Control: no-store`，避免客户端将临时故障结果长期当成真实搜索结果缓存。

前端继续按现有 `locations` 数组消费数据，因此无需修改交互流程。地点条目的 `fallback: true` 可供后续增加提示，但本次不增加新的界面文案。

## 实现边界

后端增加一个不可变的固定地点常量和一个生成兜底响应的辅助函数。所有外部故障分支统一调用该函数，避免不同错误路径返回不一致。

单次地点搜索最多发起一次腾讯地图请求。缺少 Key 时发起零次请求。代码中不增加任何重试机制。

## 测试与验证

采用测试驱动方式：

1. 先更新后端测试，覆盖缺少 Key、网络异常、额度耗尽和上游无效响应的兜底结果。
2. 测试断言上游最多调用一次，缺少 Key 时调用零次。
3. 保留无效输入返回 400、正常搜索结果透传和正常空结果的测试。
4. 所有外部结果由注入的 fetch mock 提供。
5. 运行后端单元测试、产品单元测试及使用拦截数据的浏览器冒烟测试。

部署后仅验证静态版本和普通健康状态，不请求腾讯地图或豆包 AI 的真实端点。

## 成功标准

- 仓库级约束明确禁止测试和调试循环消耗真实额度。
- 腾讯地图不可用时，用户仍能选择“深圳湖贝里”并继续生成聊天截图。
- 外部故障不会触发重试。
- Key 不出现在客户端、日志或响应中。
- 自动化验证期间腾讯地图和豆包 AI 的真实调用次数均为零。
